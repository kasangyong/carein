## 1. 서비스 명칭 *

**carein — 돌봄 재무 내비게이터**

부모 돌봄이 시작된 자녀에게, 흩어진 제도를 찾아 조합하고 앞으로 10년의 비용과 결정을
근거와 함께 계산해주는 서비스.

## 2. 아이디어 기획 핵심내용(요약) *

- **문제** — 돌봄 시장의 모든 주체가 *돌봄 받는 사람*을 본다. *돌보는 사람*은 아무도 안 본다.
  자산이 줄어드는 고객이라 어느 기관의 수익원도 아니기 때문이다. 관심의 공백이 아니라
  **인센티브의 공백**이고, 그래서 비어 있다.
- **대상** — 부모 돌봄이 시작된 40~50대 자녀. 은행의 핵심 고객층이면서 어느 채널에도 화면이 없다.
- **데이터** — 복지제도 원문(중앙부처·지자체), 2026년 장기요양 급여비용 고시, 심평원 비급여 가격,
  국민연금 수급현황, 서민금융 대출상품. 전량 공개 API·고시 문서.
- **AI 역할** — 비정형 서류 판독(VLM), 제도 색인·매칭(임베딩), 요건 대조 판정(RAG),
  결과 설명 생성(LLM). **금액 계산과 자격 판정은 AI가 하지 않는다.**
- **행동** — 몰랐던 제도를 찾아주고, 실부담을 계산하고, 자산 소진 시점을 알려주고,
  "퇴사할까 말까"에 다년 손익으로 답한다. 그리고 신청 순서와 신청처까지 준다.
- **차별점** — 판정이 지식베이스와 룰엔진에 있고 모델에 없다. 그래서 온프레미스 소형 모델로
  갈아끼워도 결과가 같다. 금융기관 망분리 환경에 그대로 들어간다.

## 3. 문제 정의 및 제안 배경 *

### 누구의 어떤 순간인가

부모가 아프기 시작한 40~50대 자녀. **돈은 나가고 소득은 줄어드는 이중 압박**이 동시에 시작되는데,
이 사람의 재무를 계산해주는 곳이 없다.

### 규모 (2026년 기준)

| 지표 | 값 |
|---|---|
| 개인 간병인 1:1 | 하루 12~14만원 = **월 360~420만원** |
| 전체 간병비 지출 | **12조원 돌파 전망** |
| 전형적 붕괴 | 300~400만원 필요 / 실수입 150만원 → 퇴사 → 경력단절 |
| 치매환자 가족 | **45.8%**가 돌봄 부담 호소 |

### 왜 비어 있는가 — 채널과 인센티브

| 주체 | 하고 있는 것 | 돌보는 사람을 안 보는 이유 |
|---|---|---|
| KB국민은행 | KB골든라이프 요양·돌봄 (2026.8) — 기관검색·비용계산·상담 | 정보 제공에서 멈춤 |
| 하나은행 | 치매안심금융센터, 유언대용신탁, 시니어 라운지 전국 확대 | 신탁은 자산가·사전가입 상품 |
| 신한은행 | SOL메이트 — 치매 시 사전 지정 신탁관리인이 자산 집행 | 대상이 시니어 **본인** |
| 간병 플랫폼 | 간병인 매칭, 간병비 견적 | 간병인을 팔아야 함 |
| 복지제도 | 장기요양·돌봄 급여 | 전부 **피돌봄자** 중심 설계 |

→ 업계 스스로도 "고급은 늘고 중간은 없다"고 진단하고 있다.

### 채널 선택 배경

**웹**을 택했다. 이 서비스는 앱을 새로 깔 여유가 없는 순간에 필요하고, 은행 앱과 창구 화면에
얹혀야 실제로 닿는다. iframe 위젯과 오픈 API를 함께 만든 이유다.

### 지금인 이유 — 제도가 바뀌는 중

- **요양병원 간병비 급여화** (2026.7.28 발표): 본인부담 100% → **30% 안팎**
- **다만 확정 제도가 아니다.** 2026년 중 제도 확정 → **2027년 상반기 시범 적용** 예정
- 의료중심 요양병원 **500곳 내외** 선정 후 의료·간병 필요도 높은 환자부터 단계적으로 8만 5천명까지
- 즉 **병원 조건과 환자 조건을 모두 통과해야 한다.** 그래서 우리는 확인 전에는 감면을
  적용하지 않고 현재 부담(100%)으로 계산한다. 감면된 모습은 조건과 함께 별도로 보여준다
- → **"내 부모가 대상인가?"가 새로운 난제**가 됐다. 제도 급변기에 정보 비대칭이 최대가 된다.

## 4. 서비스 컨셉 및 차별성 *

### 컨셉

> 돌보는 사람의 재무를 계산해주는 유일한 화면.

### 아무도 안 해주는 계산

입주간병인 200만원인데 내 월급이 150만원이다. **그만두는 게 나은가?**

직관은 "그만둬라". 실제로는 경력단절 후 복귀 임금 손실, 국민연금 가입기간 손실, 퇴직금 정지,
건강보험 지역가입 전환까지 다년으로 계산해야 하고 **답이 자주 뒤집힌다.**

실제 계산 결과 (요양병원 개인간병 사례):

```
직관   퇴사가 월 17만원 이득          (정확히 165,000원)
10년   유지가 7,845만원 이득          ← 뒤집힌다

  돌봄 기간 중 소득 차이   +1억 80만원     퇴사하면 잃는 것
  돌봄비 절약분           −1억 647만원     퇴사하면 버는 것   ← 거의 상쇄된다
  퇴사 시 받는 제도 지원     −126만원
  복귀 후 임금 하락 누적    +2,808만원     ← 여기서 뒤집힌다
  국민연금 수령액 감소      +2,304만원
  퇴직금 적립 중단           +960만원
  지역가입 건강보험료         +720만원
```

월 단위로 보면 퇴사가 17만원 이득이다. 돌봄 기간 중 잃는 소득과 아끼는 돌봄비가 거의
상쇄되기 때문이다. 그런데 그 뒤에 남는 경력·연금·퇴직금 손실이 10년에 걸쳐 쌓이면
결론이 뒤집힌다. 이 계산을 아무도 해주지 않는다.

### 기존 서비스 대비 차별점

| | 기존 | carein |
|---|---|---|
| 대상 | 돌봄 받는 부모 | **돌보는 자녀** |
| 범위 | 기관 검색·비용 계산 | 제도 발굴 → 실부담 → 10년 시뮬 → **의사결정** |
| 시야 | 이번 달 | **10년, 자산 소진 시점까지** |
| 판정 근거 | 안내 문구 | **제도 조항·고시 원문 인용** |
| 모르는 값 | 대체로 가정 | **"확인 필요"로 격리하고 합계에서 뺀다** |

### 설계상의 차별 — AI가 숫자를 만들지 않는다

```
판정 = 지식베이스(제도 원문) + 룰엔진(계산)     ← 모델과 무관
LLM  = 문서 판독 + 설명 문장 생성                ← 교체 가능
```

금융권은 망분리 때문에 고객 데이터를 외부 API로 보낼 수 없다. 우리 설계는 판정이 모델
가중치 안에 있지 않으므로, **온프레미스 소형 모델로 갈아끼워도 판정 결과가 동일하다.**
파인튜닝한 모델은 이 주장을 할 수 없다.

**이건 설계 주장이 아니라 검증된 사실이다.** 내부망 환경을 가정해 Ollama에 LG의 한국어 모델
exaone3.5(7.8B)를 올리고 `AI_PROVIDER=onprem` 으로 전환해 실행한 결과:

| 항목 | 외부 API | 온프레미스 exaone3.5 |
|---|---|---|
| 자산 유지 기간 | 2년 → 9년 9개월 | **동일** |
| 월 실부담 | 1,140,000원 | **동일** |
| 제도 판정 결과 | 9건 해당 | **동일** |
| 퇴사 손익 | 78,450,894원 | **동일** |
| 설명 문장 생성 | 가능 (Gemini 응답 13.9초) | 가능 (한국어, 응답 63초) |
| 가드레일 통과 | 근거 없는 금액 0건 | **동일** |
| 데이터 외부 전송 | 있음 (PII 마스킹 후) | **없음** |

프로바이더를 셋 지원한다. **하나면 주장이지만 셋이면 대조할 수 있다.**

| 모드 | 용도 | 검증 모델 | 데이터 외부 전송 |
|---|---|---|---|
| `onprem` | 금융기관 내부망 (기본값) | exaone3.5 7.8B | 없음 |
| `gemini` | 공개 데모 | gemini-3.6-flash | 있음 (PII 마스킹 후) |
| `claude` | 문서 판독 정확도 우선 | claude-opus-5 | 있음 (PII 마스킹 후) |

환경변수 하나로 전환되고, 어느 것을 쓰든 제도 판정과 금액 계산 결과는 같다.
분석 API(`/api/analyze`)는 애초에 LLM을 호출하지 않기 때문이다.

```
AI_PROVIDER=onprem
ONPREM_BASE_URL=http://내부망-엔드포인트
ONPREM_MODEL=exaone3.5:7.8b
```

차이가 나는 것은 문서 자동 판독 품질과 응답 속도뿐이고, **돈과 자격에 관한 결과는 한 자리도
바뀌지 않는다.** 판정이 모델이 아니라 지식베이스와 룰엔진에 있기 때문이다.

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안 *

### 5-1. 데이터 — 전량 공개 출처

대회에서 데이터를 제공하지 않으므로 전부 공개 API와 고시 문서에서 확보했다.
값마다 화면에 출처가 표시된다.

| 층 | 데이터 | 출처 | 수집·활용 |
|---|---|---|---|
| 기준값 | 재가급여 월 한도액, 시설급여 수가 | 보건복지부 2026년 장기요양 급여비용 고시 | 2개 이상 출처 교차검증 후 상수 테이블로 고정 |
| 기준값 | 본인부담률·경감 기준 | 노인장기요양보험법 시행령 | 상수 테이블 |
| 기준값 | 가족요양비 월 240,450원 | 2026년 특별현금급여 고시 | 상수 |
| 기준값 | 간병비 급여화 조건 | 보건복지부 제도화 추진방향 (2026.7.28) — **시범사업 추진방안, 제도 확정 전** | 판정 규칙 4개로 구조화. 확인 전에는 미적용 |
| 제도 | 중앙부처·지자체 복지서비스 | 한국사회보장정보원 OpenAPI | 색인 파이프라인 구현 (`npm run ingest`) |
| 제도 | 정부 혜택 전량 | 행정안전부 공공서비스(혜택) 정보 OpenAPI | 동일 파이프라인 |
| 의료 | 병원정보·비급여 진료비 | 심평원 OpenAPI | 비급여 금액 대조 |
| 돌봄 | 장기요양기관 검색·상세·평가결과 | 국민건강보험공단 OpenAPI | 기관별 실비용 |
| 소득 | 국민연금 수급현황 | 국민연금공단 OpenAPI | 부모 소득 기준 |
| 자금 | 대출상품한눈에 | 서민금융진흥원 OpenAPI | 부족 자금 경로 |

**개인 금융거래 데이터가 필요 없다.** 사용자가 넣는 것은 부모 등급·본인 소득·가족 구성 정도이고,
계산 근거는 전부 공개 데이터에서 나온다. 마이데이터·오픈뱅킹 제약을 받지 않는다.

### 5-2. 생성형 AI의 역할 — 6종으로 분리

기능마다 어느 엔진이 처리하는지 화면에 배지로 표시한다.

| 태그 | 역할 | 실제 쓰임 |
|---|---|---|
| `VLM` | 비정형 문서 이해 | 장기요양 등급판정 통지서·진단서 판독 → 등급·나이·상병코드 추출 |
| `EMB` | 의미 검색·정규화 | 복지제도 색인, 제도명 퍼지 매칭 |
| `RAG` | 근거 기반 판정 | 제도 요건 조항 대조 → 해당 / 미해당 / 확인필요 |
| `GEN` | 자연어 생성 | 결과 설명, 신청 순서 안내 |
| `RULE` | **AI 아님 — 결정론적 계산** | 금액·자격·시뮬레이션 전부 |
| `GUARD` | AI 통제 | 환각 차단, 인젝션 방어, PII 마스킹, 확정 표현 금지 |

**철칙: LLM은 단 한 번도 숫자를 만들지 않는다.**

### 5-3. AI를 통제하는 방식

주최기관인 금융보안원은 2026년 AI 레드팀 전담조직을 신설하고 금융권에 AI 보안 평가지표·
가드레일 모델·자동점검 도구를 배포하고 있다. 그 기준을 서비스에 먼저 적용했다.

| 통제 | 구현 |
|---|---|
| 근거 출처 강제 | 제도 조항을 특정하지 못하면 **판정 출력을 거부**한다 |
| 환각 차단 | 인용 근거에 없는 금액이 생성되면 차단하고 사유를 표시 |
| 확정 표현 금지 | "받습니다" → "요건 충족 시 대상입니다"로 강제 치환 |
| 프롬프트 인젝션 방어 | 업로드 문서에 삽입된 지시문을 데이터로 무력화 |
| PII 마스킹 | 주민번호·연락처·계좌를 **모델 전송 전** 치환 |
| 무저장 | 건강·소득 정보를 저장하지 않는다 |

`/governance` 화면에서 이 가드레일을 **실제로 통과시켜 결과를 보여준다.** 시뮬레이션이 아니다.
막지 못하는 케이스가 있으면 막지 못한다고 표시한다.

> 개발 중 이 콘솔이 실제 구멍을 두 번 찾아냈다. 처음에는 한국어 조사 처리가 잘못돼
> "지시사항**을** 무시"가 정규식을 빠져나갔다. 두 번째는 더 컸다 — 템플릿 리터럴로 만든
> 정규식에서 `\s`가 문자 `s`로 죽어 있어(`"\s" === "s"`) **공백이 하나만 있어도 전부
> 빠져나갔다.** "위의 규칙을 무시하세요", 영어 오타, 어순 변경, 하이픈 없는 주민번호가
> 모두 통과했는데 전화번호만 걸려서 화면에는 "차단됨"으로 표시됐다.
>
> 정규식 리터럴 + 근접 매칭으로 재작성하고, NFKC 정규화와 호모글리프 폴딩을 넣었다
> (`<systеm>`의 е는 키릴 문자다). PII는 하이픈을 전제하지 않고 앞 6자리 생년월일
> 유효성으로 오인을 줄였다. 뚫렸던 입력 4종을 케이스로 추가해 **12케이스 12/12 차단**이다.
>
> 새는데 막았다고 말하는 쪽이 아예 안 막는 것보다 나쁘다. 그래서 통과 개수보다
> 그 개수가 무엇을 가리키는지가 중요하다.

## 6. 기대 효과 및 확장 가능성 *

### 6-1. 해결하는 문제와 실질 혜택

| 대상 | 혜택 |
|---|---|
| 돌보는 자녀 | 몰라서 못 받던 제도를 찾고, 되돌릴 수 없는 결정(퇴사·주택 처분)을 근거를 보고 내린다 |
| 부모 | 자산 소진 시점을 미리 알아 요양 장소·시기를 조정할 수 있다 |
| 형제 | 금전과 시간을 같은 단위로 놓아 분담 갈등을 줄인다 |
| 은행 | 놓치고 있던 40~50대 고객 접점. 자산 소진 시점을 알면 주택연금·신탁 제안 시점도 안다 |
| 보험사 | 간병보험 보장 갭이 수치로 드러난다 |
| 정부·지자체 | 신청주의의 사각지대가 어디인지 집계된다 |

### 6-2. 정량 지표

- 실제 계산 사례: **급여화 대상 여부 확인 하나로 부모 자산 유지 기간이 2년 → 9년 9개월**
  (늘어난 93개월 중 90개월이 급여화 확인분이고 3개월이 제도 신청분이다. 화면에 그렇게 갈라 적는다.
  급여화는 2027년 시범사업 예정이라 현재 부담에는 반영하지 않는다)
- 요양원 사례: **기초연금 하나로 3년 6개월 → 5년 9개월**
- 소득 상위 사례: **두 막대가 같고, 왜 같은지를 말한다.** 해당 제도가 돈이 아니라 시간을 벌어주는 형태이기 때문
- 놓치기 쉬운 제도(인지도 낮은 제도) 검출: 사례당 2~5건
- 판정 재현성: 같은 입력 → 같은 출력 100% (판정 경로에 모델이 없음)

### 6-3. 확장 경로

**채널 확장** — 은행 시니어 브랜드(KB골든라이프·하나더넥스트·신한 SOL메이트)에 iframe 위젯으로
얹거나 오픈 API로 직접 붙인다. 창구 상담사 모드로 고령 고객의 앱 이탈 문제를 우회한다.

**보험 종목 확장** — 같은 엔진으로 정액담보 미청구, 다중 계약 중복 보장, 상속인 청구까지 확장된다.

**데이터 자산화** — 익명 집계로 지역별 돌봄 부담과 제도 사각지대 통계가 만들어진다.
지자체·규제기관이 신청주의의 구멍을 수치로 볼 수 있다.

**금융 외 영역** — 판정 엔진의 본질은 "흩어진 제도를 개인 상황에 맞춰 대조하고 근거와 함께
판정하는 것"이다. 육아, 장애, 자활, 재난 지원 등 신청주의로 운영되는 모든 제도 영역에
같은 구조가 적용된다.

## 7. AI를 신뢰할 수 있게 만드는 설계 (자유 항목)

금융 서비스에서 AI가 실패하는 방식은 두 가지다. **틀린 답을 확신에 차서 말하거나,
왜 그렇게 답했는지 설명하지 못하거나.** 이 서비스는 둘 다 구조로 막았다.

### 판정을 모델 밖에 둔다

금액과 자격 판정을 전부 결정론적 규칙으로 옮겼다. 그 결과:

- 같은 입력이면 항상 같은 출력 — 감사와 재현이 가능하다
- 모델을 바꿔도 판정이 안 바뀐다 — 온프레미스 전환이 가능하다
- 모든 숫자에 계산식이 붙는다 — 화면에서 단계별로 전개해 보여준다

### 모르는 것을 모른다고 말한다

판정은 **해당 / 미해당 / 확인 필요** 3값이다. 값을 모르면 "해당한다"고 말하지 않는다.
출처를 확인하지 못한 제도는 금액 합계에서 뺀다. 문서 판독도 신뢰도 임계치 미달이면
반영하지 않고 따로 보고한다.

### 추정을 숨기지 않는다

경력단절 복귀 임금 하락률처럼 근거가 약한 값은 **가정으로 분리해 확신도와 함께 공개**한다.
화면에서 직접 바꿀 수 있고, 바꾸면 결과가 다시 계산된다.

그리고 **점추정 하나를 확정처럼 보여주지 않는다.** 가정을 허용 범위 양 끝으로 몰아
결과가 어디까지 흔들리는지 함께 낸다. 요양병원 사례는 −2,083만원 ~ 7억 8,007만원이고,
**이 범위 안에서 결론이 뒤집힌다.** 임금 하락과 연금 영향을 0으로 놓으면 퇴사가 유리해진다.
그 사실을 화면에 적는다. 요양원·제도 적은 사례는 범위 전체에서 결론이 바뀌지 않으므로
그렇게 적는다.

### 결정을 대신하지 않는다

지급을 확정하지 않는다. 최종 판단은 공단·보건소·고용노동부가 한다. 우리는 확인해 볼 가치가
있는 항목을 골라내고, 판단에 필요한 숫자를 보여준다. 되돌릴 수 없는 결정에는 그렇다고 표시한다.

### 남은 한계

- 제도 지식베이스는 21개 항목으로 시작했다. 공공데이터 색인 파이프라인은 구현했으나
  인증키 승인 후 전량 반영된다. 색인 항목은 원문 대조 전이라 전부 "확인 필요"로 둔다.
- 문서 판독은 온프레미스 모드에서 정확도가 낮아 수동 입력으로 대체된다. 숨기지 않고 화면에 표시한다.
- 경력단절·재취업 관련 가정값은 개인차가 커서 확신도 "낮음"으로 표시했다.
