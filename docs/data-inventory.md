## 7. 개인 단위 데이터 — 구조적 제약

| 경로 | 상태 | 비고 |
|---|---|---|
| 본인 계좌 거래내역 CSV/엑셀 업로드 | **가능** | 은행 앱에서 다운로드. 팀원 본인 계좌면 실데이터 |
| 문서 업로드 (영수증·증명서·고지서) | **가능** | VLM 파싱 |
| 오픈뱅킹 API (잔액·거래내역·계좌통합조회) | **미확인** | `developers.kftc.or.kr` 테스트베드 존재. 개인/학생팀 가입 가능 여부 미검증 |
| 마이데이터 | **불가** | 본인신용정보관리업 라이선스 필요 |
| 건보공단 개인 진료내역 | **불가** | 공공마이데이터 범위 미확인 |

## 핵심 결론

```
기관 · 제도 · 통계 데이터   →  매우 풍부. API로 즉시 접근
개인 금융거래 데이터        →  없음. 업로드 아니면 불가
```

- **제도·자원을 개인 상황에 맞춰 찾아주는 서비스**는 공공데이터만으로 성립
- **개인 거래를 분석·감시하는 서비스**는 업로드 기반이어야 하고, 데모 신뢰도가 떨어짐
- 미확인 항목(오픈뱅킹 테스트베드)이 열리면 두 번째 축이 살아남

## 미검증 항목 (확인 필요)
1. 오픈뱅킹 테스트베드 개인/학생팀 가입 가능 여부 — `developers.kftc.or.kr` 직접 가입
2. 각 API의 실제 응답 필드·호출 제한 (활용신청 후 확인)
3. 복지서비스 API의 조건 검색 지원 범위 (연령·소득·지역별 필터 가능 여부)
