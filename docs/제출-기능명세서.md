## 1. MVP 구현 범위 *

배포 URL에서 **로그인이나 API 키 없이** 아래가 전부 동작한다.

| 범위 | 내용 |
|---|---|
| 화면 | 6개 — 메인(계산), 비용 지형, AI 통제, 채널 연계, 오픈 API, 임베드 위젯 |
| API | 7개 엔드포인트 (분석 1, 설명 2, 문서판독 1, 지식베이스 1, 레드팀 2) |
| 제도 지식베이스 | 21개 제도, 전 항목 근거 법령·출처 기재 |
| 기준값 | 2026년 장기요양 급여비용 고시 (2개 이상 출처 교차검증) |
| 입력 경로 | 프리셋 3종 / 직접 입력 폼 / 서류 업로드 판독 |
| 계산 | 제도 판정 · 월 실부담 · 10년 시뮬레이션 · 퇴사 손익 · 민감도 · 형제 분담 |
| AI 통제 | 가드레일 5종 + 레드팀 자기점검 8케이스 |

**모델 연결 없이도 핵심이 전부 동작한다.** 제도 판정과 금액 계산이 결정론적 규칙이기 때문이다.
모델이 필요한 것은 서류 자동 판독과 설명 문장 생성 두 가지뿐이고, 둘 다 없어도 수동 입력과
규칙 결과로 완결된다.

## 3. 사용자 이용 흐름 *

### 3-1. 기본 흐름 (심사자용, 3~5분)

```
1. 배포 URL 접속
2. "요양병원 · 개인간병" 사례 카드 클릭          (20초)
      ↓ 제도 대조 → 비용 산출 → 10년 시뮬레이션이 순서대로 실행
3. 상단 막대 확인                                  (30초)
      지금 그대로 두면      2년
      확인하고 신청하면    9년 9개월
      → 급여화 대상 확인 하나로 7년 9개월이 갈린다
4. "찾은 제도"에서 놓치기 쉬운 제도 확인             (60초)
      + 버튼으로 판정 근거·법령·신청처 전개
5. "비용이 이렇게 나옵니다"에서 계산식 전개 확인      (30초)
6. "퇴사할까, 다닐까" — 반전 확인                    (60초)
      직관: 퇴사가 월 17만원 이득
      10년: 유지가 7,845만원 이득
      → 무엇이 뒤집었는지 항목별 분해 확인
7. "지금 할 일"에서 신청 순서 확인                   (30초)
8. (선택) 헤더 "AI 통제"에서 레드팀 결과 확인        (60초)
```


## 4. AI 및 데이터 처리 방식 *

### 4-1. AI가 수행하는 역할

| 단계 | 입력 | 처리 | 출력 |
|---|---|---|---|
| 문서 판독 | 등급판정 통지서·진단서 이미지/PDF | VLM 구조화 출력 (JSON 스키마 강제) | 등급·나이·상병코드 + 필드별 신뢰도 |
| 설명 생성 | 계산이 끝난 결과 + 인용 가능한 제도 원문 | LLM 문장 생성 | 신청 순서 안내문 |

**AI가 수행하지 않는 것**: 제도 자격 판정, 금액 계산, 시뮬레이션, 손익 비교.
전부 결정론적 규칙이며 같은 입력이면 항상 같은 출력이 나온다.

### 4-2. 사용 데이터

| 구분 | 데이터 | 출처 | 처리 |
|---|---|---|---|
| 기준값 | 2026 재가급여 한도액·시설수가·본인부담률·가족요양비 | 보건복지부 고시, 시행령 | 상수 테이블. 교차검증 후 고정 |
| 제도 | 21개 제도의 요건·금액·신청처·근거법령 | 각 소관기관 공개 문서 | 판정 규칙으로 구조화 |
| 제도(확장) | 중앙부처·지자체 복지서비스, 정부 혜택 | 한국사회보장정보원·행정안전부 OpenAPI | 색인 파이프라인 (인증키 필요) |
| 의료 | 병원정보, 비급여 진료비 | 심평원 OpenAPI | 금액 대조 |
| 돌봄 | 장기요양기관 검색·상세·평가결과 | 국민건강보험공단 OpenAPI | 기관별 실비용 |

### 4-3. 개인정보·민감정보 처리 여부

| 항목 | 처리 방식 |
|---|---|
| 건강정보 (등급·진단명) | **저장하지 않음.** 요청 처리 중에만 메모리에 존재하고 응답 후 폐기 |
| 소득·자산 정보 | **저장하지 않음.** 동일 |
| 업로드 문서 | **저장하지 않음.** 판독 후 즉시 폐기. 원본을 디스크에 쓰지 않음 |
| 주민번호·연락처·계좌 | 모델 전송 **전** 정규식으로 치환. 모델에 도달하지 않음 |
| 공유 링크 | 서버가 아니라 URL 프래그먼트(`#`)에 담김. 서버 로그에 남지 않음 |
| 로그인·계정 | 없음. 개인 식별 정보를 수집하지 않음 |

**모델로 데이터가 나가는 경우**: 서류 자동 판독과 설명 생성 두 경로뿐이며, 두 경우 모두
PII 마스킹을 거친다. 금융기관 내부망 배포 시에는 환경변수 `AI_PROVIDER=onprem` 하나로
전환하면 데이터가 외부로 나가지 않으며, **판정 결과는 동일하다.** 공개 데모는 Gemini,
내부망 검증은 exaone3.5(7.8B)로 각각 실행해 결과가 일치함을 확인했다.

## 5. MVP 검증 방법 *

### 5-1. 심사자 확인 절차

| 순서 | 확인할 것 | 기대 결과 |
|---|---|---|
| 1 | 배포 URL 접속 | 로그인 없이 메인 화면 표시 |
| 2 | "요양병원 · 개인간병" 클릭 | 3초 내 결과 표시 |
| 3 | 상단 막대 | 지금 **2년** → 확인하고 신청하면 **9년 9개월**. 아래에 "대부분(7년 6개월)은 간병비 급여화 대상 확인에서 나옵니다" |
| 4 | 요약 지표 | 놓치고 있던 제도 **5개** / 월 실부담 **387만원** (확인된 제도만 반영) |
| 4-1 | "가장 큰 변수 — 간병비 급여화" 블록 | **제도 확정 전** 배지. 확인되면 387만원 → **117만원**. 대상 조건 4개와 "확인 전에는 현재 부담으로 계산" 문구 |
| 5 | "찾은 제도" 첫 행 `+` 클릭 | 판정 근거가 요건 단위로 전개. 근거 법령·출처·신청처 표시 |
| 6 | "비용이 이렇게 나옵니다" | 항목마다 계산식과 출처 표시. 합계가 위 지표와 일치 |
| 7 | "퇴사할까, 다닐까" | 좌: 퇴사(월 17만원) / 우: 유지(10년 7,845만원). **빨간 반전 경고** 표시 |
| 8 | "이 계산에 쓴 가정 7개 보기" | 값·확신도·근거 전부 표시. 확신도 "낮음" 항목이 보임 |
| 8-1 | **"경력단절 후 복귀 임금 하락률" 슬라이더를 0으로** | "1개 조정됨" 배지가 뜨고 위 손익이 **7,845만원 → 4,700만원**으로 재계산. "복귀 후 임금 하락 누적" 행이 +0원 |
| 8-2 | 그 위의 "이 숫자를 얼마나 믿어야 하나" | 범위 **−2,083만원 ~ 7억 8,007만원**, "이 범위 안에서 결론이 뒤집힙니다" 경고 |
| 8-3 | "기본값으로 되돌리기" | 원래 값으로 복귀 |
| 9 | "받을 수 있는 제도가 적은 경우" 클릭 | 미해당 제도가 다수. **전부 해당으로 나오지 않음** |
| 10 | 헤더 › AI 통제 | 레드팀 **12/12 차단**. 케이스별 입력·통과 후 대조 표시 |
| 11 | AI 통제 › 직접 시험 | 임의 문장 입력 시 3단계 가드레일 적용 결과 표시 |
| 12 | 헤더 › 비용 지형 | 6×5 매트릭스. 인지지원등급 행에 "이용 불가" 표시 |

| 14 | 탭을 옮겨가며 헤더 확인 | 5개 화면 헤더 위치·높이가 동일 |

| 지역 편차 | 지자체별 제도 차이는 색인 이후 반영된다. 현재는 중앙 제도 기준이다 |
| 설명 생성 | 모델 연결이 없으면 "AI 설명 받기"만 동작하지 않는다. 나머지는 전부 동작한다 |
